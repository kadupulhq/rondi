# Compatibility matrix

Pinned compatibility targets: RRDtool and its bundled rrdcached behavior at [v1.11.0](https://github.com/oetiker/rrdtool-1.x/releases/tag/v1.11.0); Cacti RRDProxy source revision [`54aad579803f2b9cf1e9dd979881247656853230`](https://github.com/Cacti/rrdproxy/commit/54aad579803f2b9cf1e9dd979881247656853230); Kadupul workflow checkout `release/1.2.31-97-g97538de5b`. The local RRDtool/rrdcached executables also report 1.11.0. The inspected PHP runtime had no `rrd` extension loaded; Kadupul's checked-in integration uses the configured executable and process pipes. Other C ABI consumers have not been exhaustively inventoried.

## Drop-in prerequisites and optional capabilities

Required for the stated drop-in target: interoperable in-place `.rrd` storage; the complete RRDtool command and graph behavior used by the pinned targets; unchanged Cacti polling, maintenance, graph, and export flows; and the rrdcached and RRDProxy protocols/configurations/lifecycle. These requirements are currently unmet as enumerated in [COMPATIBILITY_DEFECTS.md](COMPATIBILITY_DEFECTS.md).

Optional product capabilities: GraphQL remains a separate plugin and is not needed for storage. Remote network access is disabled; any future enablement requires explicit configuration plus authenticated transport. A `librrd` ABI is an additional packaging artifact only if native consumers are discovered; the inspected Kadupul runtime currently invokes the CLI and did not load a PHP `rrd` extension. Graph rendering should stay a separate component, but it becomes a required installed capability for existing RRDtool graph workflows.

RRDtool references: [rrdcreate](https://rrdtool.org/rrdtool/doc/rrdcreate.en.html) documents GAUGE heartbeat, PDP intervals, unknown time, AVERAGE and xfiles factor. The pinned [1.11.0 format definition](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_format.h) documents the binary `.rrd` header/layout; implementation source is maintained at [oetiker/rrdtool-1.x](https://github.com/oetiker/rrdtool-1.x).

rrdcached reference: [RRDtool's rrdcached documentation](https://www.rrdtool.org/rrdtool/doc/rrdcached.en.html) and the [rrdcached protocol manual](https://manpages.debian.org/unstable/rrdcached/rrdcached.1.en.html) specify its line-based ASCII command protocol.

Cacti RRDProxy references: [Cacti RRDProxy documentation](https://docs.cacti.net/RRDproxy.md) and the pinned [`rrdtool-proxy.php` source](https://github.com/Cacti/rrdproxy/blob/54aad579803f2b9cf1e9dd979881247656853230/rrdtool-proxy.php). The source describes encrypted client traffic, trusted clients, replication, and a separate administration socket. These protocols must not be conflated with rrdcached.

## Platform notes

RRDtool's output depends on the compiler and C library it was built with, so Rondi reproduces some of those choices per target. Each item below is selected in code by target and checked against the oracle on that platform.

- Floating-point contraction. The pinned builds fuse some `a * b + c` sites on aarch64 (Apple Clang on macOS, GCC 14.2 in the CI image) and none on x86_64. Rondi uses `rrd_mul_add`, which fuses only on aarch64, for update arithmetic, RPN (PREDICT family, STDEV) and VDEF sums. In `vdef.rs` the GCC operand split is used on Linux aarch64 and the Clang split elsewhere. In `tune` back-fill (`tune_modify.rs`, TM-43), the macOS arm64 build fuses where the Linux builds do not. Other compilers or flags can differ by one ulp.
- Double-to-integer casts. C's `(int)` and `(long)` of an out-of-range or NaN value is undefined and differs by architecture: aarch64 saturates, x86_64 returns the minimum value. Rondi follows the build target for `--zoom` sizes (`--zoom 1e30` reports `9223372036854775807` on arm64 and `9223372036854775808` on x86_64, as the oracle does) and for update times past 2^63.
- glibc `realloc(p, 0)` frees and returns NULL, so a `tune` that leaves no data sources and two or more archives fails with `Cannot allocate memory` on Linux glibc, while macOS writes the file. Rondi matches each.
- `strtoll` and friends set `EINVAL` on no conversion on Apple and FreeBSD libc but not on glibc, so restore rejects `<step>abc` on macOS and reads it as 0 on Linux glibc, as RRDtool does on each.
- libxml2. Restore models libxml2 2.9.14, the version in the CI image. macOS ships Apple's patched 2.9.13, which accepts a `<!-->` comment continued on the next stdin line; Rondi rejects it as 2.9.14 does. That is the one mismatch in 3000 mutated dumps on macOS (RD-018).
- An RRA with no rows divides by zero in RRDtool 1.11.0: on aarch64 that yields `parse_tag_rra: malloc failed.`, which Rondi matches; on x86_64 RRDtool dies with SIGFPE and Rondi reports its own error.
- RRDtool's `DNAN` is a negative quiet NaN on the pinned x86_64 build and a positive one on aarch64. Rondi stores the same bits per target (`rrd_nan` in `rrd_binary.rs` and in the rrdcached server), so stored unknowns and text such as the `tune` data source table (`-nan` on x86_64 glibc) match.
- RRDtool's `qsort` comparator for SORT, MEDIAN, PERCENT and PREDICTPERC is not a total order with NaN and infinities, so those results follow the host `qsort`; Rondi calls it. Tested on macOS and Linux glibc only.
- rrdcached half-close handling depends on when the platform raises `POLLHUP` (RD-015).
- Only 64-bit little-endian targets are supported for `.rrd` files. Other targets are not built or tested in CI.
