# Compatibility defects

Acceptance targets: RRDtool/rrdcached 1.11.0 and Cacti RRDProxy commit `54aad579803f2b9cf1e9dd979881247656853230`. These are known behavior gaps. The project must not be described as drop-in compatible while any required item remains.

| RD-001 | Complete existing `.rrd` read/write compatibility is absent. | Version 0001-0005 files open wherever `rrd_open` accepts them, including a NaN xff, `cur_row` past `row_cnt`, an empty DS name and the version 0001/0002 `time_t` live head; commands that would divide by a zero step, `pdp_cnt` or `row_cnt` refuse the file where RRDtool traps or reads garbage. fetch, create, and in-place updates work for multiple GAUGE/COUNTER/DERIVE/ABSOLUTE/DCOUNTER/DDERIVE sources and basic archives on 64-bit little-endian targets with POSIX `fcntl` locks. Differential tests cover counter wrap/reset, signed deltas, absolute rates, multi-PDP AVERAGE/MIN/MAX/LAST, xff/unknown handling, and byte equality. The split-PDP path for an irregular update followed by a multi-step unknown update now matches upstream byte-for-byte in a dedicated regression fixture. A seeded randomized differential test (100 cases over all six DS types, the four basic CFs, and fractional timestamps) compares whole files after every few updates. On aarch64 the update arithmetic fuses `a * b + c` where the pinned GCC and Clang builds of RRDtool do; other compilers or flags that change contraction can still differ by one ulp. Specialized v4/v5 features, other DS types, other ABIs, and broad interoperability remain unsupported/unverified. |
