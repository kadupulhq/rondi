# Compatibility defects

Acceptance targets: RRDtool/rrdcached 1.11.0 and Cacti RRDProxy commit `54aad579803f2b9cf1e9dd979881247656853230`. These are known behavior gaps. The project must not be described as drop-in compatible while any required item remains.

| ID | Compatibility defect | Evidence/status |

| RD-001 | Complete existing `.rrd` read/write compatibility is absent. | Version 0001-0005 files open wherever `rrd_open` accepts them, including a NaN xff, `cur_row` past `row_cnt`, an empty DS name and the version 0001/0002 `time_t` live head; commands that would divide by a zero step, `pdp_cnt` or `row_cnt` refuse the file where RRDtool traps or reads garbage. fetch, create, and in-place updates work for multiple GAUGE/COUNTER/DERIVE/ABSOLUTE/DCOUNTER/DDERIVE sources and basic archives on 64-bit little-endian targets with POSIX `fcntl` locks. Differential tests cover counter wrap/reset, signed deltas, absolute rates, multi-PDP AVERAGE/MIN/MAX/LAST, xff/unknown handling, and byte equality. The split-PDP path for an irregular update followed by a multi-step unknown update now matches upstream byte-for-byte in a dedicated regression fixture. A seeded randomized differential test (100 cases over all six DS types, the four basic CFs, and fractional timestamps) compares whole files after every few updates. On aarch64 the update arithmetic fuses `a * b + c` where the pinned GCC and Clang builds of RRDtool do; other compilers or flags that change contraction can still differ by one ulp. Specialized v4/v5 features, other DS types, other ABIs, and broad interoperability remain unsupported/unverified. |
| RD-002 | RRDtool command grammar, environment variables, stdin mode, stdout/stderr behavior, and exit codes do not match. | `rrd_tool.c` `main`, `HandleInputLine`, `fgetslong`, `CountArgs`, and `CreateArgs` are ported: argv and pipe mode (`rrdtool -`) share one dispatch table for every command, pipe lines are read as raw bytes and split only on spaces with RRDtool's quoting, and `cd`/`pwd`/`mkdir`/`ls` and the working-directory argument behave as upstream. Bytes that are not UTF-8 reach commands as U+FFFD. As a deliberate safety deviation, the output files the CLI writes itself (`graph`/`graphv` images and CSV/TSV/SSV/XML/JSON exports, `dump` XML) are opened without following a symbolic link at the last path component, and a regular file with more than one hard link is refused; RRDtool follows both. TLS transport, TCP coverage for the remaining paths, and full daemon error parity remain unimplemented. The CLI supports basic DS/RRA `create`, with `create --daemon unix:<socket>` and `RRDCACHED_ADDRESS` routing CREATE through Rondi rrdcached and a differential fetch check against an upstream-created equivalent, and at-style times through a port of `rrd_parsetime.c` and `rrd_proc_start_end` (`rondi::time`) that uses libc `localtime_r`/`mktime` like upstream. Differential tests cover parser error texts, `start time:`/`end time:` prefixes, and create, fetch and update times across DST edges in five time zones. As upstream, bare integers up to 315360000 are hours or months, not epochs. Update accepts `N`, negative relative timestamps, numeric timestamps (including fractional seconds with microsecond precision), and at-style timestamps. Numeric update times and raw DS readings use RRDtool 1.11.0's `rrd_strtod` digit accumulation and power-of-ten scaling order, exponent range check, and `nan`/`inf` spellings (GAUGE readings are byte-compared; DCOUNTER/DDERIVE pairs of infinities, NaN, finite, and non-numeric text across multi-step spans are byte-compared, and their text is converted only after a known previous sample as upstream does); a near-second-boundary fractional timestamp is differentially verified byte-for-byte on local and rrdcached update paths. Fractional numeric updates are differentially verified against RRDtool 1.11.0 byte-for-byte for both local `rrdtool update` and a batched `rrdcached UPDATE` followed by `FLUSH` on identical disposable files. Local `list` ports `rrd_list_r` and `rrd_list_rec`: readdir order, `..` refused with EACCES, globbing through libc `glob`, a name ending in `.rrd` listed as one file, directories listed unless recursing, and failures printed as `strerror(errno)` without a newline and exit 0, all differentially checked against RRDtool 1.11.0. The `rrdupdate`, `rrdcreate`, and `rrdinfo` executables (`rrdupdate.c`) are aliases of the same binary. Relative fetch/update cases, DST/calendar offsets, month-unit ambiguity, and create/update date forms are also differentially checked. General source prefill and specialized template definitions, exact diagnostics and exit parity beyond the tested cases, and other commands remain incomplete. `fetch`, `first`, `last`, `info`, `xport`, and `graphv` support the tested Rondi Unix-socket daemon paths: pending data is flushed before file-based reads, and differential output/rows match upstream after flush. Daemon FETCH does not carry `--resolution` in the pinned protocol; an integration test with multiple archives confirms that upstream RRDtool ignores that option in daemon mode, and Rondi matches it. Basic `create --daemon` routes CREATE to the daemon. These paths do not establish RRDtool daemon FETCH/network error parity. Supported narrow commands are `fetch`, `update`, `updatev`, `last`, `lastupdate`, `first`, `info`, `dump`, `restore`, `tune`, `resize`, and local `list`; full CLI parity is absent. |

Deliberate safety deviations: any listener failure, including a socket chown or chmod failure, stops startup (exit 1, sockets removed) where upstream serves the listeners that opened; a root daemon given `-U` without `-G` switches to the account's primary group where upstream keeps gid 0; a root daemon replaces its supplementary groups before setgid (`initgroups` for the `-U` account, otherwise only the `-G` group) where upstream keeps root's; ids are set real, effective, and saved together (`setresgid`/`setresuid` where available), read back, and `setuid(0)` must then fail; each Unix socket is bound, chowned, chmodded, and listening inside a private 0700 directory reached only through directory descriptors and then renamed into place, so a swapped directory, symlink, or hard link is never followed; a root daemon refuses a socket directory owned by another account, or writable by a non-root group or by others without the sticky bit, and a live socket or non-socket at the path is refused rather than unlinked; a missing socket directory is created 0755 rather than 0777 less the umask; a daemon serving as root requires effective `-B -b` confinement and Unix sockets default to 0600 unless `-m` or `-s` configures them; a stale pid file is replaced by rename, and pid and `-o` files that are symlinks or have more than one link (and, as root, pid files not owned by root) are refused. Rondi never forks, so startup failures always reach stderr, where upstream without `-g` logs them to syslog after the parent has exited 0; `-o` is opened during option parsing, as upstream does. STATS `QueueLength` counts paths queued for writing and not yet taken by a worker, as upstream does. `TreeDepth` uses an AVL cache index and matches upstream node count and height for tested live insertion/removal and journal-replay event sequences; `-f` and `-w` accept RRDtool integer or suffixed duration syntax and default to 3600 and 300 seconds respectively; the pinned `-f < 2 * -w` warning is differentially checked byte-for-byte; idle cache nodes expire at each `-f` pass, pending paths are preserved, and idle suspend state is removed. `QueueLength`, `JournalBytes`, `JournalRotate`, `UpdatesWritten`, and `DataSetsWritten` follow upstream. UPDATE checks only timestamps when queueing, keeps samples before a rejected one, and leaves value errors to the write, which drops the rest of the batch and is only logged, as upstream does; this is differentially checked. CREATE, INFO, recursive and nonrecursive LIST, UPDATE success and duplicate-timestamp responses (including fractional timestamps), LAST with pending data, FORGET, DUMP output/framing, FETCHBIN output/framing, heartbeat TUNE and suspend/resume behavior are differentially compared with upstream rrdcached on disposable fixtures. Suspended paths retain pending writes and skip explicit, periodic, and shutdown flushes until resumed. Pending memory is capped at an estimated 64 MiB and excess updates are rejected before acknowledgment, a deliberate behavior deviation to preserve the required bounded-buffer/backpressure invariant. The CLI now caps both single-line and multiline daemon responses at 1 MiB before accumulating them; valid protocol responses remain byte-identical, while oversized/non-terminating peer responses are rejected. Crash recovery and selected protocol paths have integration tests. Full options/configuration, exact framing/errors/locking semantics, and broad differential tests against upstream rrdcached remain absent. |

## Intentional differences

These are cases where matching RRDtool would mean reproducing undefined behavior, or memory aliasing inside a file that is already corrupt, so Rondi refuses or diverges on purpose. They are not planned work.

| ID | Difference | Rationale |
| --- | --- | --- |
| ID-001 | A damaged `row_cnt` whose rows lie past the end of the file makes `dump` and `resize` fail with `RRA rows extend past the end of the file`, and makes `fetch` fail with that or an overflow error when it considers that archive. | `rrd_open` sizes the archives in wrapping `unsigned long` arithmetic and checks only the wrapped total, so such a file opens, and Rondi matches that for `info`, `first`, `last`, `lastupdate`, `tune` and `update` (whose writes past the end fail with `writing rrd:` like `rrd_write`). `rrd_dump.c` walks the rows with an `unsigned int` counter, which never terminates above `UINT_MAX` rows and otherwise reads outside the mapping; `rrd_resize.c` copies once per value of the unwrapped count, so its run time and output size come from the damaged field. `rrd_fetch.c` bounds its row loop with `(signed) row_cnt`, an `int` truncation of the 64-bit count, so its result depends on that truncation and on seeks into the same unmapped range. |
| ID-002 | `dump` fails with `timestamp cannot be represented in local time` when a damaged `pdp_cnt` or `last_up` puts a row time outside the range `localtime_r` accepts. | `rrd_dump.c` ignores the `localtime_r` failure and formats an uninitialized `struct tm`, so its comment text is whatever the stack held. |
| ID-003 | When a damaged `row_cnt` makes one archive's rows alias the header or another archive, `update` writes the rows and then the header, so the header wins. | RRDtool writes both through one `mmap`, so a row stored over `rra_ptr` changes the pointer it reads for the next archive. Reproducing that needs a byte-level model of the mapping for a file that is already corrupt. |
