# RRDtool source notes

Behavioral research is pinned to RRDtool 1.11.0 (`v1.11.0`). Source was downloaded to a temporary directory for inspection; it is not copied into this repository or used at runtime.

The embedded no-argument help output for `create`, `dump`, `fetch`, `first`, `graph`, `graphv`, `info`, `last`, `lastupdate`, `list`, `resize`, `restore`, `tune`, `update`, `updatev`, and `xport` was captured from the installed RRDtool 1.11.0 executable. Regression tests compare each response's stdout (normalizing only the environment-dependent `Compiled` timestamp), stderr, and exit status against that executable. Rondi currently leaves the compile timestamp blank, so that banner field is a known output deviation. These text fixtures support only the pinned target version.

## Update path

`src/rrd_update.c` is the authority for update semantics. `_rrd_updatex` opens the existing RRD with the selected lock policy, parses update arguments, and hands each sample to `process_arg`. `process_arg` parses timestamps and values, computes the interval from `live_head.last_up` (including microseconds for version 3+), updates PDP preparation, determines crossed PDP boundaries, then advances/consolidates the CDP state and archive rows. `update_pdp_prep` handles GAUGE as `value * interval`, COUNTER/DERIVE as deltas, ABSOLUTE as the input amount per interval, uses unknown when input is `U` or heartbeat is exceeded, and applies DS min/max bounds to the rate. `update_cdp` applies xff to unknown PDP counts and handles the consolidation value. Ring pointers and archive values are persisted alongside preparation state.

This stateful procedure is why a direct formula over recent samples is insufficient for exact behavior: reopening an RRD resumes from PDP/CDP preparation state, and updates that do not cross a boundary still change that state.

## Locking and on-disk mutation

On POSIX, `src/rrd_open.c` implements whole-file advisory locks using `fcntl` record locks (`F_SETLK` or `F_SETLKW`, from byte zero to EOF). The defaults and `--locking` override are handled there. A compatible writer must coordinate through the same lock primitive; a Rust-only lock would permit upstream RRDtool and Rondi to race.

`write_changes_to_disk` in `src/rrd_update.c` writes the live header, PDP prep, CDP prep, and archive pointers back to the existing file. Archive rows are updated at their ring offsets as consolidation boundaries are crossed. The file is not replaced by a converted file. Rondi must retain the inode, honor the upstream lock convention, and preserve all unmodified definitions and archive values.

## Fetch behavior

`src/rrd_fetch.c`, specifically `rrd_fetch_fn`, selects an archive matching the requested consolidation function (with a special cross-CF allowance for one-PDP basic archives), prefers archives that cover the complete requested range, then chooses the closest resolution. It aligns request bounds to the chosen step, derives offsets from `last_up`, the archive row count, and current ring pointer, pads unavailable history/future rows with unknown values, and traverses wrapped ring storage. The source uses a shared RRD read lock for this operation.

Rondi now implements this read-only path for version 0003-0005 files on the common 64-bit little-endian layout. It reads only header metadata plus requested row values and obtains the upstream-compatible shared whole-file POSIX `fcntl` lock. Differential tests cover archive selection, multiple DS/RRAs, and CLI output; tie cases, partial overlap, unusual CFs, relative fetch-time syntax beyond integer offsets, specialized v4/v5 features, and other ABIs still need coverage.

## Current in-place update slice

`rrd_update.c`'s `process_arg`, `update_pdp_prep`, `calculate_elapsed_steps`, `simple_update`, `process_pdp_st`, `update_aberrant_cdps`, `write_to_rras`, and `write_changes_to_disk` define how source values accumulate into PDP state and how a completed PDP is committed to the archive. Rondi ports the tested integer-second path for GAUGE, COUNTER, DERIVE, ABSOLUTE, DCOUNTER, and DDERIVE sources and AVERAGE/MIN/MAX/LAST archives, including multi-PDP consolidation and configured xff. Differential fixtures now cover updates crossing multiple PDP boundaries, mixed RRA resolutions, unknown values, and retention rollover, including large gaps where RRDtool caps writes per archive and separately closes a partially open PDP. COUNTER/DERIVE text is validated and differenced as decimal integers, matching upstream `rrd_diff`, before converting the delta to the stored floating rate. The raw-decimal library, CLI, and rrdcached paths preserve samples above 2^53; the float-only convenience API remains restricted to its exactly representable integer range. DCOUNTER/DDERIVE use floating deltas, with DCOUNTER direction changes following upstream reset rules. For the tested subset, tests compare the entire file byte-for-byte with an RRDtool-updated copy, then let upstream RRDtool reopen and continue updating it. A deterministic mixed-source differential regression covers 32-bit COUNTER wrap and irregular updates for COUNTER, DERIVE, ABSOLUTE, DCOUNTER, and DDERIVE, comparing the complete file after each batch and coarser AVERAGE/MAX fetch results.

`rrd_create.c` calls `rrd_select_initial_row`, which chooses a random starting ring row. Differential update fixtures must copy one created RRD before applying parallel update sequences; independently created files can legitimately differ in their pointer and row locations even with identical definitions. A seeded sequence regression creates one upstream file per case and copies it before updates, then compares every batch byte-for-byte and checks coarser AVERAGE/MAX fetch text; using copied initial images avoids confusing the legitimate randomized starting pointer with an update difference.

RRDtool's unknown floating-point bit pattern is target-dependent. Byte comparisons on the pinned 1.11.0 builds show negative quiet NaNs on x86_64 and positive quiet NaNs on aarch64. Rondi emits the corresponding bits when it writes `.rrd` state. Text also differs by command path: local FETCH prints `-nan` on x86_64 and `nan` on aarch64, daemon FETCH prints `nan` on x86_64 and `-nan` on aarch64, and graph JSON normalizes the PRINT value to `nan` on both targets. The differential suite checks these cases against the pinned binary.

The pinned `rrd_update.c` implementation handles a long interval with an already open PDP in two phases: it proportionally splits the source integral, closes the partial PDP first, writes any completed archive rows, then processes the remaining full PDP steps. Rondi now follows that split for supported basic archives. A regression fixture with updates at `1000000010:5`, `1000000025:8`, then `1000000040:U` compares both updatev text and the complete `.rrd` bytes against RRDtool; the 20-second AVERAGE row ending at `1000000040` is `8` on both sides. This verifies the reported case, not every DS type, CF, or large-gap combination.

The Rust daemon client uses a 1 MiB bound for both one-line and multiline response reads so a peer that omits a newline cannot grow the client buffer without limit. The bound covers ordinary RRDtool 1.11.0 replies; unit tests check exact-limit acceptance and over-limit rejection. `rrd_daemon.c` keeps cache items after their pending values flush. `SUSPEND` and `SUSPENDALL` set a per-cache-item flag; periodic and explicit flush work skips suspended items. `RESUME` and `RESUMEALL` clear that flag but do not themselves write values. Rondi tracks paths created by accepted UPDATE requests and mirrors these transitions in memory; suspension state is intentionally reset after daemon restart, while pending updates still recover from the durable journal. The integration test compares the response lines, pending sample retention, and flush sequence with an upstream daemon. Cache eviction timing and all protocol command/error variants remain unverified.

The same daemon source handles `DUMP` by reading only the filename field, flushing that path if possible, writing the raw XML bytes, and closing the connection to delimit the body. Although its help syntax mentions `-h none|xsd|dtd`, this handler does not parse those trailing fields and calls the dump function with its default header. Rondi mirrors this behavior and compares default and trailing-option requests byte-for-byte with upstream; unsupported XML/file layouts remain errors rather than an assertion of full DUMP parity.

The daemon `TUNE` handler reads `<filename> <argc> <argv...>` and passes the supplied argv array unchanged to `rrd_tune_r`. Its count includes the command name in `argv[0]`; omitting that element can make the opt parser skip the first requested option while still returning success. Rondi consumes that argv[0] field and has differential coverage for the heartbeat option, including the response and in-place `.rrd` bytes. Only the basic metadata tuning subset supported by the library is implemented; prediction/seasonal parameters and step modification remain open.

The daemon `FETCHBIN` handler reuses the regular FETCH parser and archive selection, then sends five metadata lines followed by one `DSName-<name>: BinaryData <records> <record-size> <endianness>` header and native-endian doubles for each selected source. Each payload is followed by a newline, and the initial `N Success` count includes the five metadata lines and each source header. Rondi emits the same layout with its RRD fetch rows and compares the entire response with upstream, including unknown-value payloads and a selected-source request. Error text, unusual numeric layouts, and other host endianness remain unverified.

The daemon `HELP` handler looks up the requested name in its command table. A command with syntax or help text receives a `Help for <command>` response, while unknown names and entries without syntax/help receive the ordered command overview. Its `add_response_info` calls preserve extra blank lines from syntax/help strings, and those line endings determine the response count. Rondi copies the pinned table text and compares global help plus every named command, including unknown and journal-only `WROTE`, against the upstream daemon.

The daemon's `STATS` handler reports `QueueLength` as the count of cache items currently in its flush queue; suspended items with pending values are excluded because they are not enqueued. Rondi counts distinct pending paths minus suspended paths, and keeps a Rust AVL index so `TreeDepth` follows live insert/remove operations. Differential fixtures compare tree node counts and heights across ordered insertions, removals, and journal replay. Rondi's journal now records the path for FORGET events, allowing recovery to rebuild cache-tree membership in event order, including flushed entries that remain cached. The `-f` interval (default 3600 seconds) now expires idle cache nodes and clears suspend state; pending paths remain cached. Replay treats recovered cache entries as recently active, matching the daemon's recovery reset behavior. Numeric seconds are supported for `-f`; RRDtool's full scaled-duration parser remains a compatibility defect. `JournalBytes` measures Rondi's JSON journal, not RRDtool's journal byte count.

`get_time_from_reading` in `rrd_update.c` selects the timestamp grammar from the delimiter: `:` means numeric or `N`, while `@` invokes `rrd_parsetime`. Rondi accepts the `timestamp@value` form and shares its common explicit month-name and numeric calendar date parser with `create`. Its offset parser applies seconds/minutes/hours as fixed durations and days/weeks/months/years through local calendar normalization, including RRDtool's ambiguous `m` heuristic. Tests compare combined offsets, date-only forms, special times paired with dates/day names, and a DST boundary against upstream. Although the `rrd_parsetime.c` BNF lists standalone weekdays and today/yesterday/tomorrow, RRDtool 1.11.0 rejects those standalone strings in executable probes; Rondi follows that observed behavior. Special times paired with these tokens remain supported. Start/end references and subsecond timestamp persistence remain separate limitations.

This is still only a slice. Subsecond timestamps, broader bulk update combinations (especially multiple data sources and specialized archives), COMPUTE and prediction data sources/archives, other DS/CF types, specialized v4/v5 features, and other ABIs are unsupported or unverified. RD-001 remains open.

Rondi currently ports the tested v3/v4 GROW/SHRINK row mapping, requires that the output path not exist, and rejects v5; exact bytes were compared for both actions against RRDtool 1.11.0 with a wrapped cursor.
- [`rrd_format.h`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_format.h): native structures and format fields.

The numeric graph PRINT/GPRINT format validator follows the pinned `rrd_graph.c` `bad_format_print` grammar: literal text and escaped `%%`, one floating conversion with at most one flag, optional width and precision, required `l`, and an optional trailing `%s` or `%S`. Console output uses the host C `snprintf` floating conversion and RRDtool-style SI scaling for `%s`; exported scientific PRINT/GPRINT metadata has a separate formatter following the tested `rrd_snprintf.c` scaling and integer-rounding path. Differential coverage checks 32 format strings for both PRINT and GPRINT SI scale exponents -6 through 7, plus zero, negative, and unknown values. One failure-side effect remains different: with malformed printf formats, RRDtool may leave a partial JSON metadata file while Rondi leaves no output file.

`rrd_graph.c` initializes the graph plot at 400x100 pixels; `--width` and `--height` set plot dimensions, while the output canvas adds space for the axes, title, legend, and optional vertical label. `--only-graph` removes those decorations; `--full-size-mode` interprets dimensions as final canvas size. The graph helper also accepts `--force-rules-legend`, legend direction, `--border`, and color overrides for BACK/CANVAS/SHADEA/SHADEB/GRID/MGRID/FONT/AXIS/FRAME/ARROW. Rondi implements these documented controls in its PNG subset, with approximate layout/raster behavior. Its `data_proc` samples plotted definitions across each horizontal pixel, computes scale bounds from finite plotted data, and expands explicit lower/upper bounds unless `--rigid` is selected. The graph helper accepts `LINE[width]`, defaults an omitted width to 1, permits zero, rejects negative values, and passes the width to Cairo for stroke rendering; AREA initializes its line width to zero. `STACK` carries a cumulative `paintval` across line/area elements, uses the previous graph element as an AREA baseline, and propagates a prior stacked baseline across unknown samples during drawing. `skipscale` excludes the processed cumulative value from automatic graph bounds while keeping it plotted. Rondi implements cumulative LINE/AREA values, stacked AREA baselines, and the unknown-baseline case for the supported image subset. RRDtool TICK plots a vertical mark for each nonzero, known value, with a default fraction of 0.1 of graph height; positive fractions extend upward from the bottom and negative fractions downward from the top. A zero fraction draws no tick. Rondi implements those signed directions and omits zero-fraction marks, while its row-to-pixel mapping is not verified for all range and resolution boundaries. RRDtool paints HRULE/VRULE after the grid and clips them to the calculated value/time range; numeric HRULE and timestamp VRULE are implemented with those clipping rules, and neither expands data bounds. `rrdgraph_graph.pod` documents six or eight hexadecimal color digits (`#rrggbb` or `#rrggbbaa`) and AREA's optional second color and `gradheight` (default 50). Rondi parses and alpha-blends the optional alpha byte, renders an approximate two-color AREA gradient, and preserves numeric line width in its basic PNG subset. LINE/HRULE/VRULE accept default/custom dash patterns and a dash offset; Rondi parses those options and draws approximate raster dashes. VDEF-based HRULE and VRULE resolve to the aggregate value and timestamp, respectively, following `rrd_graph.c` data processing. Missing timestamps become zero, so those vertical rules fall outside ordinary epoch ranges; unknown horizontal values are not painted. `rrd_graph_helper.c::parse_hvrule` requires a previously defined VDEF and rejects DEF/CDEF references. Rules paint after LINE/AREA/TICK elements regardless of their script position, as the final rule pass in `rrd_graph.c` does. Named-versus-literal PNG comparisons and invalid-reference diagnostics are checked against RRDtool 1.11.0 on disposable files. Exact Cairo stroke/legend behavior remains unsupported. Its gradient interpolation does not reproduce Cairo's `gfx_add_rect_fadey` geometry; fixed bitmap text, approximate thick strokes, five-line grid, simple legend placement, and PNG pixels also differ from RRDtool's Pango/Cairo layout and tick selection. These remain compatibility defects rather than parity claims. The CLI also supports `--allow-shrink`, `--alt-autoscale`, `--alt-autoscale-min`, and `--alt-autoscale-max`; alternate bounds approximate RRDtool's sensible grid and are not pixel-parity verified. `--vertical-label-angle` accepts finite degrees and rotates the built-in bitmap label, whose typography is unlike RRDtool's font engine. `--imginfo` supports the safe `%s`, `%lu`, `%lu` conversions in order and `%%`; output is differentially checked, while other printf forms remain unsupported.

`rrd_xport.c` derives output columns from XPORT entries, chooses a common row step from the fetched DEF steps, aligns the requested range to that step, and emits XML or JSON metadata and rows. Rondi supports DEF/XPORT exports and row-wise CDEF evaluation for a subset of RRDtool RPN; the differential fixture checks chained CDEFs, arithmetic, comparison, IF, and unknown handling against RRDtool 1.11.0. Graph-script VDEF calculation is available as a reusable library API for all 12 pinned aggregate functions and is connected to numeric graph PRINT/GPRINT values; graphv differential integration covers AVERAGE, MAXIMUM, LAST, PERCENT, PERCENTNAN, and VDEF FIRST `strftime` output, including RRDtool's right-edge unknown buffer slot. The VDEF percentile comparator returns the host `isinf` result used by pinned `rrd_graph.c` before passing it to libc `qsort`: Darwin returns 1 for either infinity, while glibc preserves the sign. The infinity/unknown percentile fixture passes on macOS and Linux/glibc; other platforms remain unverified because the comparator does not define a portable total order. The graph/graphv CLI accepts DEF/CDEF/XPORT and basic LINE/AREA series for XML/JSON output. Numeric PRINT/GPRINT reductions over exported series cover AVERAGE/MIN/MAX/LAST with `%f`/`%e` formatting. Value timestamp/duration formatting now follows the supported PNG paths described below. The pinned valstrftime rejection fixture targets XML/JSON metadata, where `rrd_xport.c` retains numeric format validation; it does not imply that PNG value timestamps are unsupported. Raster/vector rendering, stacked calculations, `fetch --daemon` now consumes the versioned Unix-socket FETCH response and is differentially checked against RRDtool 1.11.0; the `xport --daemon` path still flushes unique DEF files through Rondi rrdcached before local export, and the rest of graph-script grammar remain open.

The xport CDEF RPN implementation also follows `rrd_rpncalc.c` for `ROUND`, radian/degree conversion, `ADDNAN`/`MINNAN`/`MAXNAN`, and stack/aggregate operations including `DEPTH`, `COPY`, `INDEX`, `ROLL`, `SORT`, `REV`, `AVG`, `MEDIAN`, `STDEV`, `PERCENT`, `SMIN`, and `SMAX`, row-state operators `PREV`, `TIME`, `COUNT`, and `STEPWIDTH`, local calendar operators `LTIME`, `NEWDAY`, `NEWWEEK`, `NEWMONTH`, and `NEWYEAR`, the `TREND`/`TRENDNAN` rolling averages, and the `PREDICT`, `PREDICTSIGMA`, and `PREDICTPERC` operators. `INDEX` truncates its argument to an integer as upstream C does; count-taking RPN operators use the same conversion for `AVG` and `COPY`, all covered by fractional-argument differential cases. Zero-count `COPY` and `ROLL` leave the stack unchanged, matching the upstream switch behavior. `AVG` and `STDEV` iterate operands in reverse stack order, as upstream does; cancellation-sensitive differential expressions ensure floating-point results preserve that order. RPN `PERCENT` and `SORT` sort unknown values before numeric values as `rpn_compare_double()` specifies; unknown-containing median-rank and stack-sort expressions are differentially checked. RRDtool uses this comparator for both operators; infinities still rely on its non-total qsort comparator. RRDtool’s comparator has non-total behavior around infinities, which remains unverified. Byte-for-byte differential fixtures exercise these operators using disposable upstream-created RRD files, including an unknown-containing trend window, prediction windows with explicit and repeated shifts, a DST offset transition, and a new-year boundary. CDEF evaluation follows `rrd_graph.c::data_calc`: each expression uses the GCD of its input steps and the intersection of their fetched ranges, then export resamples its results. Prediction pointers advance only at source-step boundaries. Differential coverage includes mixed 10/20-second sources, unknown samples, chained CDEFs, all three prediction operators, COUNT/PREV, and unaligned starts. Unaligned end ranges can expose an uninitialized extra fetch slot in upstream prediction; Rondi treats unavailable history as unknown, so allocator-dependent right-edge results remain incompatible. Extreme argument/error cases remain unverified. `NOW` uses whole-second precision, matching the upstream `time(NULL)` implementation; a concurrent differential checks its modulo-1000 value while retrying if the two processes cross a second boundary. `NEWWEEK` now follows RRDtool 1.11.0 `find_first_weekday`: on glibc it reads the active LC_TIME week metadata; on platforms without those glibc-private items it uses RRDtool’s Sunday fallback. The `rrdtool` alias initializes locale from the environment before dispatch, as upstream does. A week-boundary xport comparison passes under the available host locale; alternate locale archives are not installed in the current test environments, so other locale variants remain unverified. Remaining stateful functions are not yet implemented or verified.

Daemon FETCH numeric conversion follows `rrd_client.c::parse_value_array_header` and `rrd_strtod.c::rrd_strtodbl`, including the special NaN/infinity tokens. Values retain their non-finite identity until the CLI prints them with host C `%0.10e`, as `rrd_tool.c` does. This matters on Darwin, where printf prints both NaN signs as `nan`. A shared-response differential compares signed NaNs, infinities, case variants, and decimal rounding on macOS and Linux/glibc. The source for this pass was the RRDtool 1.11.0 release tarball, verified against SHA-256 `24c345b5c077c1b2b2fcbc1a364f1da051650fb6743ad5213096adc04c862ed4`.

`rrd_graph_helper.c::parse_comment` accepts empty positional text and the `legend=` form; `parse_textalign` accepts left/right/center/justified and `align=`. Colon escapes are removed during argument parsing, while legend controls stay in exported strings. `rrd_xport.c` emits comments and alignment entries in the same order as LINE/AREA/GPRINT. Rondi now preserves this ordering, including GPRINTs interleaved with comments and series. A disposable differential compares XML/JSON bytes and invalid/unused-argument diagnostics. PNG uses basic bitmap comment rendering and suppresses comments under `--only-graph`; full Pango layout, automatic wrapping, exact tab stops, and control spacing remain incomplete.

SHIFT follows `rrd_graph.c::data_calc`: remove the variable's old offset, truncate the replacement offset to a multiple of its consolidated step using C integer division, and move its start/end bounds. The data buffer is not refetched or rotated. Rondi's ordered calculation API now evaluates CDEF/VDEF/SHIFT together, so a CDEF consumes the source bounds available at its position and an earlier VDEF retains its original timestamp. Offsets may be literal integers or prior VDEF values. The CLI follows `rrd_graph_helper.c::parse_shift` for rejection of VDEF targets, DEF/CDEF offsets, invalid integers, and unknown targets. Differential fixtures cover positive/negative non-multiple offsets, replacement shifts, CDEF targets, dependent CDEFs, VDEF offsets, and pre/post-shift VDEF timestamps. Non-finite/out-of-range offsets are rejected instead of relying on C's undefined floating-to-integer conversion; broader grammar and extreme diagnostics remain unverified.

`rrd_graph.c::data_calc` substitutes VDEF references (including PREV(VDEF)) as scalar doubles while deriving a CDEF's step from its remaining DEF/CDEF inputs. Rondi passes aggregate doubles directly into the RPN evaluator, preserving unknowns/infinities and avoiding decimal reparsing. TREND duration operands can also come from VDEFs. Scalar-only CDEFs are rejected with the pinned missing-time-axis diagnostic. A 56-case differential compares console and JSON bytes across eight scalar expressions and seven scientific formats, including chained VDEFs and shifted sources.

Legacy PRINT reductions in `rrd_graph.c` and `rrd_xport.c` consume the complete native graph buffer, including its right-edge CDEF calculation. Rondi computes bounded summaries before export resampling/truncation; for example, an IF expression may yield zero at that extra boundary and make LAST differ from the last exported row. Exported metadata uses `rrd_snprintf.c::fmtflt` rather than console printf. The scientific subset now ports its repeated power-of-ten scaling, integer mantissa rounding, precision cap, sign, width, and padding behavior; non-finite signs follow numeric comparison rather than NaN's sign bit. The differential matrix passes on macOS ARM64 and the pinned Linux/glibc container. Extreme exponent ranges fall back to the existing host formatter, and other conversions/platforms remain unverified; this is not a complete `rrd_snprintf` port.

PNG GPRINT values now use the calculated graph formatter output and remain in script order among comments and series labels. Legend line controls align the complete row; explicit multiline rows reserve canvas space and bottom-up direction reverses rows without reversing their fragments. Numeric GPRINTs and equivalent comments produce identical PNGs within each engine in disposable RRDtool/Rondi comparisons, including no-legend, only-graph, and full-size options. The `\s` and `\u` controls adjust the following row; `bottomup2` reverses the legend between its first and last non-comment entries, preserving header/footer comments. Disposable differential fixtures cover both controls and the reversal. Bitmap fonts, wrapping, spacing, and tabs still differ or remain unverified; PNG legends are bounded to 256 rows.

`rrd_fetch.c` seeks to the initial ring position and again at wraparound. Rondi now follows that sequence with a bounded 64 KiB read buffer and reused row scratch space under the existing shared lock. A differential fixture crosses both buffer and ring boundaries with four sources, distinct value blocks, and padded ranges. `rrd_graph_helper.c::parse_cdef` parses each expression once; `rrd_graph.c::data_calc` reuses `rpnstack` across calculations. Rondi now retains CDEF token boundaries and stack capacity across rows, clearing the stack for each evaluation. Local before/after profiles and measured workloads are recorded in [benchmarks.md](benchmarks.md).

`rrd_graph_helper.c` maps `valstrftime` and `valstrfduration` to timestamp/duration `vformatter` values. `rrd_graph.c::timestamp_to_tm` truncates the numeric value and uses `gmtime_r`, while `strfduration` divides milliseconds by 1000, derives components by repeated division, truncates requested precision before printf, and emits a single leading negative sign. Rondi ports those paths and the 200-byte buffer boundary. `rrd_xport.c` ignores `vformatter` for metadata, but console PRINT still uses graph `print_calc`; the earlier valstrftime rejection fixture exercises the export path, not PNG support. Differential tests now cover the supported timestamp/duration formats on both paths and compare GPRINT with equivalent comments inside each engine. Full named-argument, extreme-range, and buffer-failure diagnostics remain incomplete.
