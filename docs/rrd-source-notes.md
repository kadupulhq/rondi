# RRDtool source notes

Behavioral research is pinned to RRDtool 1.11.0 (`v1.11.0`). Source was downloaded to a temporary directory for inspection; it is not copied into this repository or used at runtime.

The embedded no-argument help output for `create`, `dump`, `fetch`, `first`, `graph`, `graphv`, `info`, `last`, `lastupdate`, `list`, `resize`, `restore`, `tune`, `update`, `updatev`, and `xport` was captured from the installed RRDtool 1.11.0 executable. Regression tests compare each response's stdout (normalizing only the environment-dependent `Compiled` timestamp), stderr, and exit status against that executable. Rondi currently leaves the compile timestamp blank, so that banner field is a known output deviation. These text fixtures support only the pinned target version.

## Update path

`src/rrd_update.c` is the authority for update semantics. `_rrd_updatex` opens the existing RRD with the selected lock policy, parses update arguments, and hands each sample to `process_arg`. `process_arg` parses timestamps and values, computes the interval from `live_head.last_up` (including microseconds for version 3+), updates PDP preparation, determines crossed PDP boundaries, then advances/consolidates the CDP state and archive rows. `update_pdp_prep` handles GAUGE as `value * interval`, COUNTER/DERIVE as deltas, ABSOLUTE as the input amount per interval, uses unknown when input is `U` or heartbeat is exceeded, and applies DS min/max bounds to the rate. `update_cdp` applies xff to unknown PDP counts and handles the consolidation value. Ring pointers and archive values are persisted alongside preparation state.

This stateful procedure is why a direct formula over recent samples is insufficient for exact behavior: reopening an RRD resumes from PDP/CDP preparation state, and updates that do not cross a boundary still change that state.

## Locking and on-disk mutation

On POSIX, `src/rrd_open.c` implements whole-file advisory locks using `fcntl` record locks (`F_SETLK` or `F_SETLKW`, from byte zero to EOF). The defaults and `--locking` override are handled there. A compatible writer must coordinate through the same lock primitive; a Rust-only lock would permit upstream RRDtool and Rondi to race.

`write_changes_to_disk` in `src/rrd_update.c` writes the live header, PDP prep, CDP prep, and archive pointers back to the existing file. Archive rows are updated at their ring offsets as consolidation boundaries are crossed. The file is not replaced by a converted file. Rondi must retain the inode, honor the upstream lock convention, and preserve all unmodified definitions and archive values.

## Fetch behavior

`src/rrd_fetch.c`, specifically `rrd_fetch_fn`, selects an archive matching the requested consolidation function (with a special cross-CF allowance for one-PDP basic archives), prefers archives that cover the complete requested range, then chooses the closest resolution. It aligns request bounds to the chosen step, derives offsets from `last_up`, the archive row count, and current ring pointer, pads unavailable history/future rows with unknown values, and traverses wrapped ring storage. The source uses a shared RRD read lock for this operation.

Rondi now implements this read-only path for version 0003-0005 files on the common 64-bit little-endian layout. It reads only header metadata plus requested row values and obtains the upstream-compatible shared whole-file POSIX `fcntl` lock. Differential tests cover archive selection, multiple DS/RRAs, and CLI output; tie cases, partial overlap, unusual CFs, relative fetch-time syntax beyond integer offsets, specialized v4/v5 features, and other ABIs still need coverage.

## Current in-place update slice

`rrd_update.c`'s `process_arg`, `update_pdp_prep`, `calculate_elapsed_steps`, `simple_update`, `process_pdp_st`, `update_aberrant_cdps`, `write_to_rras`, and `write_changes_to_disk` define how source values accumulate into PDP state and how a completed PDP is committed to the archive. Rondi ports the tested integer-second path for GAUGE, COUNTER, DERIVE, ABSOLUTE, DCOUNTER, and DDERIVE sources and AVERAGE/MIN/MAX/LAST archives, including multi-PDP consolidation and configured xff. Differential fixtures now cover updates crossing multiple PDP boundaries, mixed RRA resolutions, unknown values, and retention rollover, including large gaps where RRDtool caps writes per archive and separately closes a partially open PDP. COUNTER/DERIVE text is validated and differenced as decimal integers, matching upstream `rrd_diff`, before converting the delta to the stored floating rate. The raw-decimal library, CLI, and rrdcached paths preserve samples above 2^53; the float-only convenience API remains restricted to its exactly representable integer range. DCOUNTER/DDERIVE use floating deltas, with DCOUNTER direction changes following upstream reset rules. For the tested subset, tests compare the entire file byte-for-byte with an RRDtool-updated copy, then let upstream RRDtool reopen and continue updating it.

`rrd_create.c` calls `rrd_select_initial_row`, which chooses a random starting ring row. Differential update fixtures must copy one created RRD before applying parallel update sequences; independently created files can legitimately differ in their pointer and row locations even with identical definitions.

RRDtool's unknown floating-point bit pattern is target-dependent. Byte comparisons on the pinned 1.11.0 builds show negative quiet NaNs on x86_64 and positive quiet NaNs on aarch64. Rondi emits the corresponding bits when it writes `.rrd` state. Text also differs by command path: local FETCH prints `-nan` on x86_64 and `nan` on aarch64, daemon FETCH prints `nan` on x86_64 and `-nan` on aarch64, and graph JSON normalizes the PRINT value to `nan` on both targets. The differential suite checks these cases against the pinned binary.

The pinned `rrd_update.c` implementation handles a long interval with an already open PDP in two phases: it proportionally splits the source integral, closes the partial PDP first, writes any completed archive rows, then processes the remaining full PDP steps. Rondi now follows that split for supported basic archives. A regression fixture with updates at `1000000010:5`, `1000000025:8`, then `1000000040:U` compares both updatev text and the complete `.rrd` bytes against RRDtool; the 20-second AVERAGE row ending at `1000000040` is `8` on both sides. This verifies the reported case, not every DS type, CF, or large-gap combination.

`rrd_daemon.c` keeps cache items after their pending values flush. `SUSPEND` and `SUSPENDALL` set a per-cache-item flag; periodic and explicit flush work skips suspended items. `RESUME` and `RESUMEALL` clear that flag but do not themselves write values. Rondi tracks paths created by accepted UPDATE requests and mirrors these transitions in memory; suspension state is intentionally reset after daemon restart, while pending updates still recover from the durable journal. The integration test compares the response lines, pending sample retention, and flush sequence with an upstream daemon. Cache eviction timing and all protocol command/error variants remain unverified.

The same daemon source handles `DUMP` by reading only the filename field, flushing that path if possible, writing the raw XML bytes, and closing the connection to delimit the body. Although its help syntax mentions `-h none|xsd|dtd`, this handler does not parse those trailing fields and calls the dump function with its default header. Rondi mirrors this behavior and compares default and trailing-option requests byte-for-byte with upstream; unsupported XML/file layouts remain errors rather than an assertion of full DUMP parity.

The daemon `TUNE` handler reads `<filename> <argc> <argv...>` and passes the supplied argv array unchanged to `rrd_tune_r`. Its count includes the command name in `argv[0]`; omitting that element can make the opt parser skip the first requested option while still returning success. Rondi consumes that argv[0] field and has differential coverage for the heartbeat option, including the response and in-place `.rrd` bytes. Only the basic metadata tuning subset supported by the library is implemented; prediction/seasonal parameters and step modification remain open.

The daemon `FETCHBIN` handler reuses the regular FETCH parser and archive selection, then sends five metadata lines followed by one `DSName-<name>: BinaryData <records> <record-size> <endianness>` header and native-endian doubles for each selected source. Each payload is followed by a newline, and the initial `N Success` count includes the five metadata lines and each source header. Rondi emits the same layout with its RRD fetch rows and compares the entire response with upstream, including unknown-value payloads and a selected-source request. Error text, unusual numeric layouts, and other host endianness remain unverified.

The daemon `HELP` handler looks up the requested name in its command table. A command with syntax or help text receives a `Help for <command>` response, while unknown names and entries without syntax/help receive the ordered command overview. Its `add_response_info` calls preserve extra blank lines from syntax/help strings, and those line endings determine the response count. Rondi copies the pinned table text and compares global help plus every named command, including unknown and journal-only `WROTE`, against the upstream daemon.

The daemon's `STATS` handler reports `QueueLength` as the count of cache items currently in its flush queue; suspended items with pending values are excluded because they are not enqueued. Rondi counts distinct pending paths minus suspended paths, and keeps a Rust AVL index so `TreeDepth` follows live insert/remove operations. Differential fixtures compare tree node counts and heights across ordered insertions, removals, and journal replay. Rondi's journal now records the path for FORGET events, allowing recovery to rebuild cache-tree membership in event order, including flushed entries that remain cached. The `-f` interval (default 3600 seconds) now expires idle cache nodes and clears suspend state; pending paths remain cached. Replay treats recovered cache entries as recently active, matching the daemon's recovery reset behavior. Numeric seconds are supported for `-f`; RRDtool's full scaled-duration parser remains a compatibility defect. `JournalBytes` measures Rondi's JSON journal, not RRDtool's journal byte count.

`get_time_from_reading` in `rrd_update.c` selects the timestamp grammar from the delimiter: `:` means numeric or `N`, while `@` invokes `rrd_parsetime`. Rondi accepts the `timestamp@value` form and shares its common explicit month-name and numeric calendar date parser with `create`. Its offset parser applies seconds/minutes/hours as fixed durations and days/weeks/months/years through local calendar normalization, including RRDtool's ambiguous `m` heuristic. Tests compare combined offsets, date-only forms, special times paired with dates/day names, and a DST boundary against upstream. Although the `rrd_parsetime.c` BNF lists standalone weekdays and today/yesterday/tomorrow, RRDtool 1.11.0 rejects those standalone strings in executable probes; Rondi follows that observed behavior. Special times paired with these tokens remain supported. Start/end references and subsecond timestamp persistence remain separate limitations.

This is still only a slice. Subsecond timestamps, broader bulk update combinations (especially multiple data sources and specialized archives), COMPUTE and prediction data sources/archives, other DS/CF types, specialized v4/v5 features, and other ABIs are unsupported or unverified. RD-001 remains open.

## Pinned source files

- [`rrd_update.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_update.c): argument parsing, timestamps, PDP and CDP processing, archive writes, state persistence. [`rrd_diff.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_diff.c) subtracts integer DS values from their decimal strings before converting the result to double.
- [`rrd_update.c` `rrd_update`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_update.c): `--daemon` selects `rrdc_update` after `rrdc_connect`; without the option the library also consults `RRDCACHED_ADDRESS`. Rondi now sends supported updates through the rrdcached `UPDATE` line over a Unix socket, leaving ownership and durable journaling to the daemon. Remote TCP addresses and the full rrdcached client connection behavior remain unsupported.
- [`rrd_fetch.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_fetch.c): archive selection, range alignment, ring-buffer traversal, and padding.
- [`rrd_open.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_open.c): format open, locking, offsets, and file IO.
- [`rrd_create.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_create.c): initialization of DS/RRA state and randomized initial ring positions.
- [`rrd_daemon.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_daemon.c): line protocol, cache-item lifetime, BATCH responses, suspend/resume state, flush scheduling, and daemon lifecycle.
- [`rrd_list.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_list.c): directory traversal, POSIX glob handling, recursive wildcard rejection, and list output formatting.
- [`rrd_restore.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_restore.c): XML parsing, PDP/CDP preparation restoration, archive-row loading and rotation, range checking, and output creation. Rondi restores only its tested basic v3/v5 DS/CF subset and does not resolve external DTDs.
- [`rrd_graph.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_graph.c): graph PRINT/GPRINT validation and formatting, SI autoscaling, data processing, and graph output behavior.
- [`rrd_tune.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_tune.c): option parsing and writes to the stat header, DS definitions, and RRA definitions. The current port implements heartbeat, min/max, basic data-source type, and rename edits to DS definitions; type changes reset `last_ds` to `UNKN`. Other options dispatch to specialized logic or file modification paths that remain unsupported.
- [`rrd_resize.c`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_resize.c): resize creates the fixed `resize.rrd` output, inserts or removes rows relative to the RRA ring pointer, adjusts row count/pointer metadata, and supports format versions 1, 3, and 4 in the pinned source. Rondi currently ports the tested v3/v4 GROW/SHRINK row mapping, requires that the output path not exist, and rejects v5; exact bytes were compared for both actions against RRDtool 1.11.0 with a wrapped cursor.
- [`rrd_format.h`](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_format.h): native structures and format fields.

The numeric graph PRINT/GPRINT format validator follows the pinned `rrd_graph.c` `bad_format_print` grammar: literal text and escaped `%%`, one floating conversion with at most one flag, optional width and precision, required `l`, and an optional trailing `%s` or `%S`. Output uses the host C `snprintf` floating conversion and RRDtool-style SI scaling for `%s`. Differential coverage checks 32 format strings for both PRINT and GPRINT SI scale exponents -6 through 7, plus zero, negative, and unknown values. One failure-side effect remains different: with malformed printf formats, RRDtool may leave a partial JSON metadata file while Rondi leaves no output file.

`rrd_graph.c` initializes the graph plot at 400x100 pixels; `--width` and `--height` set plot dimensions, while the output canvas adds space for the axes, title, legend, and optional vertical label. `--only-graph` removes those decorations; `--full-size-mode` interprets dimensions as final canvas size. The graph helper also accepts `--force-rules-legend`, legend direction, `--border`, and color overrides for BACK/CANVAS/SHADEA/SHADEB/GRID/MGRID/FONT/AXIS/FRAME/ARROW. Rondi implements these documented controls in its PNG subset, with approximate layout/raster behavior. Its `data_proc` samples plotted definitions across each horizontal pixel, computes scale bounds from finite plotted data, and expands explicit lower/upper bounds unless `--rigid` is selected. The graph helper accepts `LINE[width]`, defaults an omitted width to 1, permits zero, rejects negative values, and passes the width to Cairo for stroke rendering; AREA initializes its line width to zero. `STACK` carries a cumulative `paintval` across line/area elements, uses the previous graph element as an AREA baseline, and propagates a prior stacked baseline across unknown samples during drawing. `skipscale` excludes the processed cumulative value from automatic graph bounds while keeping it plotted. Rondi implements cumulative LINE/AREA values, stacked AREA baselines, and the unknown-baseline case for the supported image subset. RRDtool TICK plots a vertical mark for each nonzero, known value, with a default fraction of 0.1 of graph height; positive fractions extend upward from the bottom and negative fractions downward from the top. A zero fraction draws no tick. Rondi implements those signed directions and omits zero-fraction marks, while its row-to-pixel mapping is not verified for all range and resolution boundaries. RRDtool paints HRULE/VRULE after the grid and clips them to the calculated value/time range; numeric HRULE and timestamp VRULE are implemented with those clipping rules, and neither expands data bounds. `rrdgraph_graph.pod` documents six or eight hexadecimal color digits (`#rrggbb` or `#rrggbbaa`) and AREA's optional second color and `gradheight` (default 50). Rondi parses and alpha-blends the optional alpha byte, renders an approximate two-color AREA gradient, and preserves numeric line width in its basic PNG subset. LINE/HRULE/VRULE accept default/custom dash patterns and a dash offset; Rondi parses those options and draws approximate raster dashes. Rule forms sourced from VDEFs and exact Cairo stroke/legend behavior remain unsupported. Its gradient interpolation does not reproduce Cairo's `gfx_add_rect_fadey` geometry; fixed bitmap text, approximate thick strokes, five-line grid, simple legend placement, and PNG pixels also differ from RRDtool's Pango/Cairo layout and tick selection. These remain compatibility defects rather than parity claims. The CLI also supports `--allow-shrink`, `--alt-autoscale`, `--alt-autoscale-min`, and `--alt-autoscale-max`; alternate bounds approximate RRDtool's sensible grid and are not pixel-parity verified. `--vertical-label-angle` accepts finite degrees and rotates the built-in bitmap label, whose typography is unlike RRDtool's font engine. `--imginfo` supports the safe `%s`, `%lu`, `%lu` conversions in order and `%%`; output is differentially checked, while other printf forms remain unsupported.

`rrd_xport.c` derives output columns from XPORT entries, chooses a common row step from the fetched DEF steps, aligns the requested range to that step, and emits XML or JSON metadata and rows. Rondi supports DEF/XPORT exports and row-wise CDEF evaluation for a subset of RRDtool RPN; the differential fixture checks chained CDEFs, arithmetic, comparison, IF, and unknown handling against RRDtool 1.11.0. Graph-script VDEF calculation is available as a reusable library API for all 12 pinned aggregate functions and is connected to numeric graph PRINT/GPRINT values; graphv differential integration covers AVERAGE, MAXIMUM, LAST, PERCENT, PERCENTNAN, and VDEF FIRST `strftime` output, including RRDtool's right-edge unknown buffer slot. The VDEF percentile comparator now returns the signed infinity result used by pinned `rrd_graph.c` before passing it to libc `qsort`; ordering with infinities remains unverified because that comparator does not define a portable total order. The graph/graphv CLI accepts DEF/CDEF/XPORT and basic LINE/AREA series for XML/JSON output. Numeric PRINT/GPRINT reductions over exported series cover AVERAGE/MIN/MAX/LAST with `%f`/`%e` formatting. Time formatting outside the tested VDEF/strftime path, SI scaling, duration/valstrftime formatting, raster/vector rendering, stacked calculations, `fetch --daemon` now consumes the versioned Unix-socket FETCH response and is differentially checked against RRDtool 1.11.0; the `xport --daemon` path still flushes unique DEF files through Rondi rrdcached before local export, and the rest of graph-script grammar remain open.

The xport CDEF RPN implementation also follows `rrd_rpncalc.c` for `ROUND`, radian/degree conversion, `ADDNAN`/`MINNAN`/`MAXNAN`, and stack/aggregate operations including `DEPTH`, `COPY`, `INDEX`, `ROLL`, `SORT`, `REV`, `AVG`, `MEDIAN`, `STDEV`, `PERCENT`, `SMIN`, and `SMAX`, row-state operators `PREV`, `TIME`, `COUNT`, and `STEPWIDTH`, local calendar operators `LTIME`, `NEWDAY`, `NEWWEEK`, `NEWMONTH`, and `NEWYEAR`, the `TREND`/`TRENDNAN` rolling averages, and the `PREDICT`, `PREDICTSIGMA`, and `PREDICTPERC` operators. Byte-for-byte differential fixtures exercise these operators using disposable upstream-created RRD files, including an unknown-containing trend window, prediction windows with explicit and repeated shifts, a DST offset transition, and a new-year boundary. Prediction parity is only checked for same-resolution data; mixed-resolution alignment and extreme argument/error cases remain unverified. `NOW` is implemented but has not been compared due to its wall-clock dependence. Locale-specific first-weekday behavior and remaining stateful functions are not yet implemented or verified.
