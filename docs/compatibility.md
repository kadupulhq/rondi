# Compatibility matrix

Pinned compatibility targets: RRDtool and its bundled rrdcached behavior at [v1.11.0](https://github.com/oetiker/rrdtool-1.x/releases/tag/v1.11.0); Cacti RRDProxy source revision [`54aad579803f2b9cf1e9dd979881247656853230`](https://github.com/Cacti/rrdproxy/commit/54aad579803f2b9cf1e9dd979881247656853230); Kadupul workflow checkout `release/1.2.31-97-g97538de5b`. The local RRDtool/rrdcached executables also report 1.11.0. The inspected PHP runtime had no `rrd` extension loaded; Kadupul's checked-in integration uses the configured executable and process pipes. Other C ABI consumers have not been exhaustively inventoried.

Status values describe the current implementation against those targets.

| Area | Status | Boundary |
| --- | --- | --- |
| GAUGE data-source semantics | Partial | Fixed step, heartbeat, unknown samples, and time-weighted PDP values are implemented; differential coverage is still being completed. |

Raw-decimal library, CLI, and rrdcached paths preserve COUNTER/DERIVE values above 2^53 and match tested updates byte-for-byte. The float-only convenience API remains precision-limited; boundary and input/error parity remain open. |

Differential tests cover parser errors and create/fetch/update times across DST edges in UTC, America/New_York, Europe/Berlin, Asia/Kolkata and Australia/Lord_Howe. A localhost differential case covers create, update, fetch, first, last, and flushcached against upstream rrdcached; created files are read with RRDtool and their fetched rows are compared. Update template column mapping, unknown-name handling, arity diagnostics, and duplicate-name file bytes are differentially checked; create-time `--template` copies the supported basic DS/RRA structure and inherits step and last-update unless overridden; missing-template and duplicate-DS errors are differentially checked. `create --source` supports one source with matching basic DS/RRA definitions and inherits its last-update time; fetched rows are compared with RRDtool. Multi-source prefill, mappings, differing start, known-data prefill across differing steps, daemon mode, specialized definitions, and COMPUTE remain unsupported; differing-step prefill is supported only for a source with unknown archive data. `first`, `last`, `fetch`, `xport`, and `graphv --daemon` route tested operations through a selected Unix socket; TCP interoperability is additionally exercised for `first`, `last`, and `fetch` against upstream rrdcached. `create --daemon` sends CREATE to Rondi rrdcached. `fetch --daemon` parses the versioned daemon FETCH response, and output is differentially matched with RRDtool 1.11.0 against the same daemon. Unknown values are parsed as NaN and displayed as `nan` by this CLI. `xport --daemon` still flushes each unique DEF file before reading locally. TCP for `xport`, `graphv`, and other untested paths plus complete connection/error parity remain incomplete. `xport` supports DEF/XPORT XML or JSON plus a row-wise CDEF subset. DEF `:step=`, `:start=`, `:end=`, `:reduce=`, and `:daemon=` options are parsed like `rrd_graph_helper.c`, including `\:` escapes; a step finer than requested (per DEF or export-wide) is consolidated with a port of `rrd_reduce_data`, and these cases are differentially tested. A CDEF over a DEF with its own `start=`/`end=` window is not yet limited to that window as RRDtool does, and `daemon=` is untested. Its byte-for-byte differential fixtures cover chained definitions, arithmetic, comparisons, conditional and unknown-value behavior, numeric and NaN-aware operators, stack manipulation, aggregates, percentile selection, `TREND`/`TRENDNAN`, `PREDICT`/`PREDICTSIGMA`/`PREDICTPERC` for tested same-resolution windows and explicit/repeated shifts, `PREV`/`PREV(variable)`/`TIME`/`COUNT`/`STEPWIDTH`, and local calendar operators across new-year and DST boundaries. graph/graphv XML/JSON export with explicit DEF/CDEF/XPORT elements is differentially tested; Graph-command VDEF integration (library VDEF aggregation is implemented and tested; percentile ordering involving infinities remains unverified), mixed-resolution rows where RRDtool reads outside its buffers, complete RPN coverage, advanced time formatting, and mixed-resolution CDEF corner cases remain unsupported or unverified. No-argument help for supported RRDtool commands, missing-file `first`/`last`/`lastupdate`/`info`/`dump`/`fetch`/`update`/`tune`/`resize`, the malformed-row diagnostics for `update` (missing separator, excess values, invalid timestamp, and invalid GAUGE value, missing source readings), and `create` missing-archive/data-source diagnostics match pinned output except for the environment-dependent `Compiled` timestamp in help banners. | rrdcached protocol | Partial | The `rrdcached` alias accepts a tested subset of ASCII commands over a Unix socket, including typed INFO and LIST output for supported common layouts, FORGET, FETCHBIN, DUMP, basic TUNE, HELP, STATS, and SUSPEND/RESUME/SUSPENDALL/RESUMEALL. Global HELP and per-command HELP responses for the pinned command table, including unknown/WROTE fallback behavior, match upstream text and framing under differential tests. `rrdcached -h` and `--help` match the pinned option listing, stdout, and exit status. `-a <size>` defaults to one, controls per-file pending update-entry vector growth in Rondi, and matches upstream zero-value diagnostics/status; Rondi batches journal samples differently from upstream’s cache array, so allocator layout is not identical. `-s <group>` resolves group names or numeric IDs, applies socket ownership and the upstream `0760` group mode, and is differentially checked against the current primary group; an explicit `-m` mode overrides that mode. Invalid groups match upstream stderr/exit behavior. `-P <commands>` accepts named command permissions and denies disallowed recognized commands with upstream framing; PING/UPDATE denial plus always-available HELP are differentially tested. The current single-listener configuration does not reproduce multiple listener permission scopes. `-m <octal-mode>` sets the Unix socket mode and matches a disposable upstream socket at mode `0660`; invalid modes match upstream stderr and exit status. Without `-m` or `-s`, Unix socket permissions now come from bind-time process umask like upstream; differential integration covers the default and explicit `0660` modes. `-R` is accepted; CREATE refuses missing parent directories by default and creates them recursively only with `-R`, as pinned source requires. `-t` defaults to the upstream value of four; positive values are accepted and bound concurrent periodic and shutdown flush workers. Invalid numeric values match the pinned error text, stderr, and exit status. This does not yet reproduce upstream's worker-queue scheduling for explicit FLUSH/FLUSHALL commands. FETCHBIN reproduces the tested binary payload framing and native-endian double layout, including differential coverage for selected and multiple data sources with unknown values. STATS `QueueLength` counts paths scheduled for flush and excludes suspended files. `PENDING` retains all accepted buffered values; `QUEUE` now represents only paths scheduled after the `-w` age threshold. Deterministic unit coverage checks threshold scheduling and FIFO order, but live upstream `QUEUE` timing/order parity remains unverified. The daemon accepts `-j <directory>` and stores its synced Rondi journal there as a single append-only JSON-lines file (defaulting to the storage root); this does not reproduce upstream journal rotation or record format. Explicit `-p <file>` writes the foreground process PID, rejects a live owner, replaces stale PID files, and removes its own file on shutdown; the upstream default PID path is not used. `-o <file>` appends structured JSON lifecycle/operational events, but its logger format, levels, and rotation behavior are not upstream-compatible. It also accepts `-B`, `-F`, and `-g`; their path confinement, shutdown flush, and foreground behavior are always enabled by Rondi. `-f` runs the periodic eligibility/expiry pass; `FLUSHALL` and graceful shutdown drain all accepted pending writes. `TreeDepth` uses a Rust AVL index and matches upstream heights for tested live insertion/removal and journal-replay event sequences; `-f` and `-w` accept RRDtool integer or suffixed duration syntax (`-f` defaults to 3600 seconds and `-w` to 300 seconds); startup emits the pinned `-f < 2 * -w` warning and has byte-for-byte differential coverage; idle nodes expire through journaled events; pending paths remain cached and idle suspend state is removed. `JournalBytes` uses the Rondi journal size, so STATS remains partial. DUMP emits unframed XML and closes its connection; trailing header options are ignored like pinned RRDtool source. TUNE currently handles heartbeat, min/max, basic DS type, and rename options, with the upstream argc/argv[0] protocol shape. CREATE, INFO, recursive and nonrecursive LIST, UPDATE success and duplicate timestamp responses, LAST with pending data, FORGET, FETCHBIN output/framing, DUMP output/framing, heartbeat TUNE, and suspended flush behavior are compared with upstream rrdcached on disposable fixtures. It journals accepted updates before acknowledgment, applies bounded pending-queue backpressure, and replays pending updates after restart. Network listeners, full option/configuration parity, exact framing/error/lifecycle behavior, and complete upstream command coverage remain unsupported. |

## Drop-in prerequisites and optional capabilities

Required for the stated drop-in target: interoperable in-place `.rrd` storage; the complete RRDtool command and graph behavior used by the pinned targets; unchanged Cacti polling, maintenance, graph, and export flows; and the rrdcached and RRDProxy protocols/configurations/lifecycle. These requirements are currently unmet as enumerated in [COMPATIBILITY_DEFECTS.md](COMPATIBILITY_DEFECTS.md).

Optional product capabilities: GraphQL remains a separate plugin and is not needed for storage. Remote network access is disabled; any future enablement requires explicit configuration plus authenticated transport. A `librrd` ABI is an additional packaging artifact only if native consumers are discovered; the inspected Kadupul runtime currently invokes the CLI and did not load a PHP `rrd` extension. Graph rendering should stay a separate component, but it becomes a required installed capability for existing RRDtool graph workflows.

RRDtool references: [rrdcreate](https://rrdtool.org/rrdtool/doc/rrdcreate.en.html) documents GAUGE heartbeat, PDP intervals, unknown time, AVERAGE and xfiles factor. The pinned [1.11.0 format definition](https://github.com/oetiker/rrdtool-1.x/blob/v1.11.0/src/rrd_format.h) documents the binary `.rrd` header/layout; implementation source is maintained at [oetiker/rrdtool-1.x](https://github.com/oetiker/rrdtool-1.x).

rrdcached reference: [RRDtool's rrdcached documentation](https://www.rrdtool.org/rrdtool/doc/rrdcached.en.html) and the [rrdcached protocol manual](https://manpages.debian.org/unstable/rrdcached/rrdcached.1.en.html) specify its line-based ASCII command protocol.

Cacti RRDProxy references: [Cacti RRDProxy documentation](https://docs.cacti.net/RRDproxy.md) and the pinned [`rrdtool-proxy.php` source](https://github.com/Cacti/rrdproxy/blob/54aad579803f2b9cf1e9dd979881247656853230/rrdtool-proxy.php). The source describes encrypted client traffic, trusted clients, replication, and a separate administration socket. These protocols must not be conflated with rrdcached.

The current test suite includes 3 native GAUGE semantic differential cases, 16 disposable `.rrd` binary layout/update/fetch cases, and CLI output comparisons against RRDtool 1.11.0. The binary cases include byte-for-byte in-place updates for the supported DS/CF subsets and checks that upstream RRDtool can continue updating the resulting files. A deterministic differential regression now generates eight irregular GAUGE update sequences (including unknowns and heartbeat gaps), checks each batch against full-file bytes, and compares AVERAGE/MAX fetch output at a coarser resolution. The checked-in Kadupul `rrd_init()` template-update stream also passes as a disposable byte-for-byte smoke test. These are still bounded fixtures, not broad parity coverage: malformed-input diagnostics, all command flags and defaults, graph definitions, full daemon protocols, and the C ABI remain unverified or unsupported. No complete parity claim is made. See [compatibility defects](COMPATIBILITY_DEFECTS.md).
