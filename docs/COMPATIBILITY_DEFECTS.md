# Compatibility defects

Acceptance targets: RRDtool/rrdcached 1.11.0 and Cacti RRDProxy commit `54aad579803f2b9cf1e9dd979881247656853230`. These are known behavior gaps. The project must not be described as drop-in compatible while any required item remains.

| ID | Compatibility defect | Evidence/status |
| --- | --- | --- |
| RD-001 | Complete existing `.rrd` read/write compatibility is absent. | Common version 0003-0005 layouts can be inspected; fetch, create, and in-place updates work for multiple GAUGE/COUNTER/DERIVE/ABSOLUTE/DCOUNTER/DDERIVE sources and basic archives on 64-bit little-endian targets with POSIX `fcntl` locks. Differential tests cover counter wrap/reset, signed deltas, absolute rates, multi-PDP AVERAGE/MIN/MAX/LAST, xff/unknown handling, and byte equality. The split-PDP path for an irregular update followed by a multi-step unknown update now matches upstream byte-for-byte in a dedicated regression fixture. Specialized v4/v5 features, other DS types, other ABIs, and broad interoperability remain unsupported/unverified. |
| RD-002 | RRDtool command grammar, full at-style time parsing, environment variables, stdin mode, stdout/stderr behavior, and exit codes do not match. | The `rrdtool` alias supports stdin command mode (`rrdtool -`) with line-based dispatch, quit, status markers, tested `update --template` processing through a Kadupul-style multi-command session, and `--skip-past-updates` for stale samples. A narrow `updatev` implementation is differentially checked for text and byte-level file changes, including a partial-PDP split followed by an unknown multi-step update. `update --daemon unix:<socket>` and `RRDCACHED_ADDRESS=unix:<socket>` now route accepted writes through the daemon; integration coverage uses Rondi rrdcached and upstream RRDtool fetch after flush. The CLI client transport now handles upstream `host:port` addresses for command, update, and multiline request paths; a disposable local test checks Rondi create, update, fetch, first, last, and flush against upstream rrdcached, including reading remote-created files with upstream RRDtool. TLS transport, TCP coverage for the remaining paths, complete option ordering, and full daemon error parity remain unimplemented. The CLI supports basic DS/RRA `create`, with `create --daemon unix:<socket>` and `RRDCACHED_ADDRESS` routing CREATE through Rondi rrdcached and a differential fetch check against an upstream-created equivalent, numeric timestamps, `now +/- fixed duration` create starts, month-name and numeric calendar dates, special times paired with dates/day names (for example `noon yesterday`), RRDtool's suffixed fixed-duration syntax, and combined fixed/calendar offsets for seconds through years using local calendar/DST rules. Standalone weekday and today/yesterday/tomorrow references are rejected by pinned RRDtool 1.11.0 (confirmed by executable differential probes); the broad BNF comment in `rrd_parsetime.c` does not describe accepted standalone input. Special times paired with those day tokens remain supported. Rondi matches upstream stderr for these rejected create-start inputs in a differential regression test. Fetch positive integer times are epochs; zero and negative integers are relative to now. Fetch/xport/graph range options resolve `start±offset` and `end±offset` relative to the paired endpoint, with differential coverage for fetch, xport, and graphv, plus rejection coverage for self/mutually relative ranges. Update accepts `N`, negative relative timestamps, numeric timestamps, and at-style timestamps with supported date forms; subsecond numeric input is truncated to whole seconds by the current storage layer. Local `list` wildcard output, unmatched-pattern errors, recursive-wildcard errors, and recursive traversal through directory symlinks are differentially checked against RRDtool 1.11.0; the pinned executable follows the tested symlink and lists its `.rrd` entries. Relative fetch/update cases, DST/calendar offsets, month-unit ambiguity, and supported create/update date forms are also differentially checked. General source prefill and specialized template definitions, exact diagnostics and exit parity beyond the tested cases, and other commands remain incomplete. `fetch`, `first`, `last`, `info`, `xport`, and `graphv` support the tested Rondi Unix-socket daemon paths: pending data is flushed before file-based reads, and differential output/rows match upstream after flush. Basic `create --daemon` routes CREATE to the daemon. These paths do not establish RRDtool daemon FETCH/network error parity. Supported narrow commands are `fetch`, `update`, `updatev`, `last`, `lastupdate`, `first`, `info`, `dump`, `restore`, `tune`, `resize`, and local `list`; full CLI parity is absent. |
| RD-003 | Complete COUNTER, DERIVE, and ABSOLUTE compatibility is absent. | Basic COUNTER wrap, DERIVE signed deltas, ABSOLUTE rates, and DCOUNTER/DDERIVE floating delta/reset semantics are differentially checked on disposable v3/v5 fixtures. Seeded mixed-source sequences now exercise COUNTER wrap together with irregular timestamp intervals across COUNTER, DERIVE, ABSOLUTE, DCOUNTER, and DDERIVE; every update batch is compared byte-for-byte and AVERAGE/MAX fetch text is checked. The raw-decimal library path, `rrdtool update`, and rrdcached server path preserve COUNTER/DERIVE integer text and match RRDtool byte-for-byte for tested values above 2^53, including a one-count delta. Float-only `update_rrd_values` remains limited to exactly representable integers, and boundary/input/error parity is incomplete. |
| RD-004 | Create-time templates, source prefill, and exact source-specific command parsing are incomplete. | Basic `.rrd` creation selects version 0003 for GAUGE/COUNTER/DERIVE/ABSOLUTE and version 0005 for DCOUNTER/DDERIVE; version 0003-0005 updates support those sources with per-source bounds and heartbeat. `rrdtool update --template` maps sample columns by data-source name and unknown-name and too-few/too-many value diagnostics are differentially checked; duplicate template names produce byte-identical updates to RRDtool. `create --template` copies step, DS/RRA structure, and (when not overridden) last-update time for the tested supported DS/CF subset; missing-template and duplicate-DS diagnostics match upstream. A single `--source` with exactly matching supported DS/RRA definitions is prefilled from its dump, inherits the source last-update time, and is verified with upstream fetch; matching basic schema with a different step is supported and differentially checked when the source has only unknown archive data. Missing, malformed, and non-regular source paths plus existing-target/`--no-overwrite` diagnostics and precedence are differentially checked. Multiple sources, schema remapping, differing start, known-data differing-step prefill, daemon mode, and broad prefill alignments remain unsupported. Structural cloning for specialized DS/RRA definitions, COMPUTE data sources, and full source-specific parsing also remain unsupported; `.rondi` remains a separate scalar-series format. |

Differential output covers dependent CDEFs; arithmetic, comparison, IF, UNKN, ROUND, angular conversion, NaN-aware math/min/max, aggregate and stack functions, PERCENT rank selection, `PREV` and `PREV(variable)` (including first-row unknown and previous-source values at the tested common resolution), TIME, COUNT, STEPWIDTH, TREND/TRENDNAN including unknown windows, PREDICT/PREDICTSIGMA/PREDICTPERC for tested same-resolution windows and explicit or repeated shifts, LTIME across a DST transition, and calendar changes across a new-year boundary. | RD-006 | Graph expressions, existing graph definitions, and output formats are incomplete. | `graph` and `graphv` handle XML/JSON export, and graphv accepts `--daemon` through the Rondi Unix-socket flush path with `DEF`, `CDEF`, `XPORT`, basic `LINE` and `AREA` series, and `PRINT`/`GPRINT` numeric formatting for AVERAGE/MIN/MAX/LAST over exported series. | RD-007 | Full rrdcached command line, line protocol, responses, connection lifecycle, daemon configuration, and service behavior do not match upstream. | A Unix-socket subset is implemented for PING, UPDATE, FLUSH/FLUSHALL, FORGET, PENDING/QUEUE, LAST/FIRST, INFO/LIST, FETCH/FETCHBIN, DUMP, a basic TUNE subset, STATS, CREATE, BATCH, SUSPEND/RESUME/SUSPENDALL/RESUMEALL, HELP, and QUIT. Buffered accepted updates are now distinct from paths scheduled for disk flush: `PENDING` reports buffered values, while `QUEUE` reports only paths past `-w`; one live cache-queue unit test covers threshold scheduling and FIFO insertion order. The live `QUEUE` timing and FIFO behavior has not yet been successfully differentially verified against upstream. The daemon's `-f` timer schedules eligible values and idle-node expiry, while `FLUSHALL` and graceful shutdown drain all accepted pending updates. `-a` accepts positive chunk sizes, defaults to one, and matches invalid-zero diagnostics/status; it applies chunking to Rondi’s journal update entries rather than RRDtool’s sample-value arrays, so internal allocation behavior remains a deviation. `-s` resolves a group, assigns socket group ownership, and uses the upstream `0760` mode unless `-m` overrides it; valid and invalid group cases are differentially tested. `-P` restricts recognized protocol commands and matches a pinned Unix-socket differential case; multiple listeners and all unusual permission combinations remain unverified. `-m` applies explicit octal socket permissions and valid/invalid behavior is differentially checked; Rondi now leaves default bind-time permissions to the process umask, matching upstream; explicit `-m` and `-s` modes remain differentially checked. `-R` now gates CREATE parent-directory creation (off by default), with integration coverage for denial and success; path confinement remains enabled. `-t` has upstream's default of four; positive values set concurrent periodic and shutdown flush workers, and the invalid-zero diagnostic is differentially checked. Explicit protocol FLUSH/FLUSHALL do not yet share upstream worker-pool scheduling. FETCHBIN emits the upstream text preamble followed by native-endian IEEE-754 doubles and the per-data-source binary record framing; selected-source, multi-source, and unknown-value responses are compared byte-for-byte against upstream. DUMP sends unframed XML and closes the connection to signal end-of-response; the daemon ignores trailing DUMP header options and always emits the default DTD, matching pinned source. TUNE accepts a command argc plus argv fields (including the `tune` argv[0] token) and currently supports heartbeat, min/max, basic DS type, and DS rename changes. Global HELP command overview and HELP output for every command-table entry, including unknown/WROTE fallback behavior, are compared with pinned source for text and framing. Daemon `-h` and `--help` output and exit status now match the pinned executable byte-for-byte. Option `-j <directory>` selects the directory for Rondi's synced append-only JSON-lines journal and restart replay; upstream journal rotation/format are not matched. Explicit `-p <file>` PID ownership and cleanup are implemented, including stale-file replacement and active-process rejection; SIGINT/SIGTERM handlers are installed before the listener socket is published, preventing an immediate post-start signal from leaving stale PID or socket files; the upstream default PID path is deliberately not used, and PID locking/race behavior is not fully equivalent. `-o <file>` appends Rondi structured tracing output; upstream syslog/log-file formatting, verbosity controls, and rotation semantics are not matched. Options `-B`, `-F`, and `-g` are accepted; Rondi always confines paths to its base directory, flushes on graceful shutdown, and remains in the foreground. STATS `QueueLength` counts distinct non-suspended queued paths and is differentially exercised with multiple UPDATE requests for one suspended file. `TreeDepth` uses an AVL cache index and matches upstream node count and height for tested live insertion/removal and journal-replay event sequences; `-f` and `-w` accept RRDtool integer or suffixed duration syntax and default to 3600 and 300 seconds respectively; the pinned `-f < 2 * -w` warning is differentially checked byte-for-byte; idle cache nodes are expired through journaled events, pending paths are preserved, and idle suspend state is removed. `JournalBytes` counts Rondi JSON journal bytes rather than upstream journal bytes. CREATE, INFO, recursive and nonrecursive LIST, UPDATE success and duplicate-timestamp responses, LAST with pending data, FORGET, DUMP output/framing, FETCHBIN output/framing, heartbeat TUNE and suspend/resume behavior are differentially compared with upstream rrdcached on disposable fixtures. Suspended paths retain pending writes and skip explicit, periodic, and shutdown flushes until resumed. UPDATE acknowledgment follows `sync_data` of a JSON-lines journal entry; replay restores pending entries. Pending memory is capped at an estimated 64 MiB and excess updates are rejected before acknowledgment, a deliberate behavior deviation to preserve the required bounded-buffer/backpressure invariant. The CLI now caps both single-line and multiline daemon responses at 1 MiB before accumulating them; valid protocol responses remain byte-identical, while oversized/non-terminating peer responses are rejected. Crash recovery and selected protocol paths have integration tests. TCP, full options/configuration, exact framing/errors/locking semantics, and broad differential tests against upstream rrdcached remain absent. |
| RD-008 | Cacti RRDProxy daemon startup/lifecycle, client/proxy wire protocols, encryption, allowlists, replication, config wizard, and admin behavior are unsupported. | A packaged `rrdtool-proxy.php` adapter now forwards process arguments and standard streams to the shared Rust executable. | RD-009 | No `librrd`-compatible shared library or C ABI is built. | The checked Kadupul tree has no `RRDs::` calls, direct PHP RRD-extension calls, or `extension=rrd` configuration. `lib/rrd.php` invokes the RRDtool executable in local mode and has a separate TCP/RSA-protected RRDProxy path. Existing checked-in Kadupul workflows therefore do not require a shared library. A librrd-compatible artifact remains unsupported for external applications that link to the C ABI. |

| RD-011 | Unchanged Kadupul polling, maintenance, graph, export, and RRDProxy workflows have not passed against Rondi. | `scripts/smoke-kadupul-poller.sh` invokes the checked-in `lib/rrd.php` `rrd_init()` helper unchanged, streams the same CRLF `update --skip-past-updates --template` commands to pinned RRDtool 1.11.0 and Rondi, and compares complete disposable `.rrd` files byte-for-byte; this focused poller-session smoke passes. | RD-014 | RRDtool `flushcached` address, error, and all argument behavior is incomplete. | The `rrdtool flushcached` command matches pinned RRDtool 1.11.0 for no-argument help, missing daemon configuration, explicit `--daemon` precedence over `RRDCACHED_ADDRESS`, environment fallback, multi-file success (including a filename containing whitespace), and first-failure text against a Unix-socket Rondi daemon. A new localhost TCP differential test uses upstream rrdcached, queues updates through both upstream and Rondi clients, then flushes through Rondi and checks the resulting file with upstream RRDtool. TLS addresses and broad TCP connection/error cases remain compatibility defects. |

The upstream RRDtool and rrdcached executables can interoperate only with `.rrd` binary state. A `.rondi` file must never be substituted for one.
