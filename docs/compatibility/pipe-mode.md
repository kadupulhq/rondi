# Pipe mode

This specification describes `rrdtool -`, the mode in which RRDtool 1.11.0
reads commands from standard input, one per line, and answers each on
standard output. `rrdtool(1)` calls it remote control; MRTG, Cacti and
similar programs drive RRDtool this way. It covers how the mode starts, how
input lines are read and split into arguments, the built-in commands `cd`,
`mkdir`, `pwd`, `ls` and `quit`, the `OK` and `ERROR:` replies, error
recovery and the exit status. It is written for an implementer who has not
seen RRDtool's source.

Command dispatch on the command line, option parsing, the usage text and
the command output formats are in [cli.md](cli.md); this document refers to
them. Provenance tags and classes (**must**, **should**, **defect**,
**undefined**) have the meaning given there:

- **[doc]** `rrdtool(1)` (REMOTE CONTROL) and the help of `cd`, `mkdir`,
  `pwd`, `ls` and `quit`;
- **[bb]** black-box runs of RRDtool 1.11.0, recorded in the vector table;
- **[rsi]** reference-source inspection. No rule in this document needed
  it.

## Compatibility tests

The vectors are the `pipe-*` entries of
`crates/rondi-cli/tests/data/cli_spec_vectors.json`, replayed by
`crates/rondi-cli/tests/cli_spec_vectors.rs` and generated by
`scripts/cli-spec-vectors.py` (see [cli.md](cli.md) for the format, the
fixture and the normalization). A pipe vector runs `rrdtool -` (optionally
with a work directory) with the vector's `stdin`, written as Latin-1 bytes,
and compares the whole of standard output, standard error and the exit
status. Groups: `pipe-session` (151 sessions), `pipe-workdir` (9) and
`pipe-env` (3).

## 1. Starting and ending

**PM-1** (doc, bb; must). `rrdtool -` reads commands from standard input
until end of file or `quit` (PM-21), then exits with status 0. The status
is 0 even when commands failed.

**PM-2** (bb; must). With empty input nothing is printed and the status
is 0.

**PM-3** (doc, bb; must). `rrdtool - <dir>` changes the working directory
to `<dir>` before reading. An empty `<dir>` is ignored.

**PM-4** (bb; must). If that directory change fails, the program writes
`ERROR: chdir <dir> <system error text>` (no colon after the directory)
and a newline to standard error, reads no input, and exits with the
system error number as its status (2 for a missing directory, 20 for a
file).

**PM-5** (doc, bb; defect). `rrdtool(1)` says the program changes its root
directory to `<dir>` when run by root. RRDtool 1.11.0 does not: as root it
only changes directory, `pwd` shows the full path, and `cd ..` and `cd /`
leave `<dir>`. Observed in the Linux container as root; the vectors cover
the visible effect (`pipe-workdir-006`).

**PM-6** (bb; must). `rrdtool - <dir> <more>` (three or more arguments) is
not pipe mode: it fails with `ERROR: unknown function '-'` on standard
error and status 1 ([cli.md](cli.md) CLI-4).

## 2. Reading lines

**PM-7** (bb; must). Input is read as bytes, not text. A line ends at a
newline byte; the newline is not part of the line. The last line need not
end with a newline. There is no line length limit (lines of several
thousand bytes and hundreds of arguments are handled, `pipe-session-120`
to `-124`).

**PM-8** (bb; defect). A NUL byte ends the visible text of its line: the
bytes after it up to and including the next newline are discarded, and
the line then continues with the next input line, which is appended to the
text before the NUL. So `last a.rrd<NUL>\nlast a.rrd\n` is read as one line
`last a.rrdlast a.rrd` (two arguments, a usage error) and the second
command is lost; `<NUL>\nlast a.rrd\n` runs `last a.rrd` once; a NUL at
the end of input simply ends the line. Pinned by `pipe-session-118`,
`-119`, `-147` to `-151`.

**PM-9** (bb; must). Before splitting, bytes at the start and at the end
of the line are removed while they are space or control characters (byte
values 1 to 32). Tabs and carriage returns therefore do not matter at the
ends (`last a.rrd\r\n` works), but inside the line they are ordinary
characters (PM-10). Byte 127 is not removed.

**PM-10** (bb; should). On macOS arm64 and Linux x86_64 bytes 128 to 255
at the ends of a line are also removed (`\xfflast a.rrd` and
`last a.rrd\xe9` run `last a.rrd`); on Linux aarch64 they are kept and
become part of the first or last argument. The vectors record both
(`pipe-session-143`, `-144`, `-146`). This follows the signedness of the
C `char` type on each platform; a replacement reproduces the platform's
reference behavior.

## 3. Splitting into arguments

**PM-11** (bb; must). The trimmed line is split into arguments at runs of
space characters (byte 32 only). Tabs and other bytes are part of an
argument (`last\ta.rrd` is one argument).

**PM-12** (bb; must). Single quotes and double quotes group characters,
including spaces, into one argument. The quote characters are removed. A
quoted part can be adjacent to unquoted text or to another quoted part
and they join into one argument (`'a'.rrd`, `"a.r"'rd'`). Inside single
quotes a double quote is an ordinary character and the other way round
(`'a".rrd'` is `a".rrd`). An empty quoted string is an empty argument
(`last ""` opens `''`; `last "" a.rrd` has two arguments).

**PM-13** (bb; must). Backslash and `#` are ordinary characters; there is
no escaping and no comment syntax. A line starting with `#` is a command
named `#` (PM-16). If a quote is not closed by the end of the line (this
includes `"a\"b"` and the shell idiom `'it'\''s'`), the line is rejected
with `ERROR: creating arguments` on standard output, no `OK` line, and
the session continues.

## 4. Replies

**PM-14** (doc, bb; must). After a command that succeeds, its output (if
any) is followed by one line `OK u:<user> s:<system> r:<real>`, each value
printed with two decimals. `<user>` and `<system>` are the CPU seconds the
process has used so far, `<real>` the wall-clock seconds since the session
started. The values are not deterministic; the vectors normalize the line
to `OK u:* s:* r:*`. A replacement must keep the format (digits, a point,
two digits).

**PM-15** (doc, bb; must). A command that fails prints `ERROR: <message>`
on **standard output** (not standard error) and no `OK` line. The message
is the one the command would print on the command line, cut to 4095 bytes
([cli.md](cli.md) CLI-35). Text that a failing command prints before its
error (the `-1` of `last` and `first`) is kept. The session continues
with the next line; failures do not change the exit status.

**PM-16** (bb; must). A line is dispatched on its arguments:

1. No arguments (an empty or blank line), or exactly one argument that is
   not `quit`, `pwd`, `ls`, `cd` or `mkdir` (`foo`, `help`, `version`,
   `info`, `last`, `#`, `-`, `-v`, `QUIT`, `LS`, `""`, `'last a.rrd'`):
   the pipe-mode usage (PM-18) and an `OK` line.
2. The built-in commands of section 5.
3. Two or more arguments whose first is `help`, `--help`, `-h` or `-?`:
   the pipe-mode usage and `OK`. Unlike the command line, `help last`
   does not print the help of `last`.
4. Two or more arguments whose first is `version`, `--version` or `-v`:
   the version line of [cli.md](cli.md) CLI-4 and `OK`.
5. Two or more arguments whose first is a command name: the command runs
   with the remaining arguments, exactly as on the command line, and
   replies as in PM-14 or PM-15. The output of `graph`, `xport`, `fetch`,
   `info` and the others is the command-line output.
6. Anything else with two or more arguments (`foo bar`, `# comment`,
   `- x`, `Last a.rrd`): `ERROR: unknown function '<first>'`, no `OK`.

**PM-17** (doc, bb; must). Command names, including the built-in ones, are
case-sensitive.

**PM-18** (bb; must). The pipe-mode usage is the generic usage of
[cli.md](cli.md) CLI-8 with one more paragraph after the command list:
an empty line and `Valid remote commands: quit, ls, cd, mkdir, pwd`. The
exact bytes are pinned by `pipe-session-002` and the other usage
vectors.

**PM-19** (bb; must). Errors that the command line writes without a
`ERROR:` prefix (the `list` errors of [cli.md](cli.md) CLI-74) still go
to standard error in pipe mode, and the command is followed by `OK`.

**PM-20** (bb; must). Environment variables are read as on the command
line: `RRDCACHED_ADDRESS` applies to every command in the session
([cli.md](cli.md) CLI-41, CLI-42), and `TZ` to the time formats.

## 5. Built-in commands

**PM-21** (doc, bb; must). The built-in commands take a fixed number of
arguments. A wrong count prints
`ERROR: invalid parameter count for <name>` and no `OK`:

| Command | Arguments | Effect |
|---|---|---|
| `quit` | none | ends the session immediately (PM-1); later lines are not read |
| `pwd` | none | prints the absolute working directory, then `OK` |
| `ls` | none | lists the working directory (PM-22), then `OK` |
| `cd` | one | changes the working directory, then `OK` |
| `mkdir` | one | creates one directory, then `OK` |

`quit x` is therefore an error and the session goes on. A line `"quit"`
(quoted) or ` quit ` (blanks) quits.

**PM-22** (doc, bb; must). `ls` prints `d <name>` for every entry of the
working directory that is a directory, including `.` and `..`, and
`- <name>` for every regular file whose name ends in `.rrd`. Other entries
are not listed. The order is the directory enumeration order and is not
specified; the vectors sort these lines (see [cli.md](cli.md)).

**PM-23** (bb; must). `cd` to a path that does not exist or is not a
directory prints `ERROR: chdir <path> <system error text>` (no colon after
the path; an empty path gives `chdir  No such file or directory` with two
spaces) and leaves the directory unchanged. `cd ..`, `cd /` and relative
paths work as usual; the change lasts for the rest of the session and
affects later commands' relative file names.

**PM-24** (bb; must). `mkdir` creates one level only, with the default
permissions. Failures print `ERROR: mkdir <path>: <system error text>`
(with a colon): `File exists` for an existing file or directory,
`No such file or directory` for a missing parent or an empty name.

**PM-25** (doc, bb; must). The built-in commands exist only in pipe mode;
on the command line they are unknown functions or help topics
([cli.md](cli.md) CLI-3, CLI-4).

## 6. Robustness

**PM-26** (doc, bb; must). Every line gets exactly one reply: output and `OK`,
an `ERROR:` line, or nothing for `quit` (and nothing for the empty visible
text of PM-8). A replacement must not stop reading after an error, must
not wait for more input than one line before replying, and must flush its
reply before reading the next line, so that a client can wait for `OK` or
`ERROR:` after each command.

**PM-27** (bb; must). Non-UTF-8 bytes in arguments are passed through
unchanged, in file names and in error messages (`pipe-session-117`,
`-145`).

**PM-28** (bb; must). A replacement must handle lines of at least 64 KiB
and at least 1000 arguments per line without crashing, and must not
allocate memory proportional to anything but the input it has read.

## Known divergences

Vectors that fail against Rondi at the time of writing are listed in
`KNOWN_DIVERGENCES` in `crates/rondi-cli/tests/cli_spec_vectors.rs` with a
reason; the expectation stays RRDtool's. For pipe mode they are the
daemon fallback of [cli.md](cli.md) CLI-42 (`pipe-env-001`, `-002`,
`pipe-session-132`), the 4095-byte message limit (`pipe-session-121`),
non-UTF-8 bytes in error messages (`pipe-session-117`, `-145`), and on
Linux aarch64 the end-of-line trimming of bytes 128 to 255, which Rondi
applies on every platform (`pipe-session-143`, `-144`, `-146`).
